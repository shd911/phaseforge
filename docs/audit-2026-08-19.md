## CRITICAL

### C1. Custom-кроссовер: порядок игнорируется в экспортируемом FIR
`fir/iir_path.rs:215-219` — для `FilterType::Custom` каскад = **один** биквад,
`cfg.order` отброшен («Order field is informational here»). Аналитическая
модель (`target/mod.rs::custom_lp_complex/custom_hp_complex`) каскадирует
`order/2` секций + 1-й порядок для нечётных. UI (`CrossoverDialog.tsx:85`)
предлагает порядки 1–8, `dispatch.rs:72` шлёт Custom в IIR-маршрут.

Замер (Custom HP 100 Hz Q=0.707, 16384 тапов @48k, 20–1000 Hz):

| order | max Δmag | max Δφ | модель | FIR |
|---|---|---|---|---|
| 1 | 13.8 dB | 84.9° | 5.9 dB/окт | 12.2 |
| 2 | 0.04 dB | 0.0° | 12.0 | 12.2 |
| 4 | 27.9 dB | 163.5° | 24.1 | 12.2 |
| 8 | 83.7 dB | 179.8° | 48.1 | 12.2 |

Корректен только order=2. Защитный ФВЧ на драйвере при order=4/8 экспортируется
вчетверо-ввосьмеро более пологим, чем показан.

**Фикс:** зеркалить `custom_*_complex` в `build_filter_cascade`, либо
`is_iir_realizable` отвергает Custom с `order != 2` (уход в cepstral).
Плюс тест паритета крутизны для порядков 1–8.

`pipeline_contract` это не ловит — там `tilt = 0`.

## HIGH

### H1. «Единая конвенция пика N/2» не выполняется (сошлись 4 источника)
Два независимых дефекта:

1. **IIR-путь центрирует начало, а не пик.** `iir_path.rs:426`: итоговый пик =
   `raw_peak_idx + shift`, а `raw_peak_idx` у НЧ-каскада — сотни отсчётов.
   Замер: LR4 LP 80 Hz, 16384 → пик 8758 при half=8192 (+566 отсч. = 11.8 мс).
   Цепстральный путь на той же полосе даёт ровно 8192.
2. **Адаптивный сдвиг схлопывается на коротких тапах.** `shift = half.min(n-1-last_significant)`
   → 0, когда хвост выше −100 dB на последнем отсчёте.
   LR4 HP 20 Hz / 4096 тапов → shift=0, пик в нуле (недолёт 2048 = 42.7 мс).
   Bessel BP 30–300 / 16384 → рассинхрон 4787 отсч. (100 мс).
   Gaussian BP 80–500 → 774 отсч. (16 мс).

Плюс: `last_significant` считается в cepstral на **полуоконном** импульсе, в IIR —
на сыром каскаде. Для одной полосы LR4 HP 30 @4096 это 757 vs 0 — переключение
одного XO в linear-phase меняет латентность WAV на сотни отсчётов без сигнала в UI.

`tests/wav_peak_convention.rs` закреплён на 16384 тапах и трёх фикстурах, где
хвост успевает затухнуть — вся область отказа не покрыта. Утверждение в
CLAUDE.md «ЕДИНАЯ — все пути кладут пик у N/2» неверно.

**Фикс:** `shift = half.saturating_sub(raw_peak_idx).min(n-1-last_significant)`
для IIR; вернуть фактический сдвиг в `FirModelResult` и показывать латентность
полосы числом; расширить приёмку кейсами 4096/20 Hz, Bessel/Gaussian BP.

### H2. Экспорт считается на другой частотной сетке, чем превью
`fir-export.ts:24` зовёт `evaluateBandFull` **без** `freq` → evaluator берёт
`measurement.freq`; Export-таб (`FrequencyPlot.tsx:1765`) строит свою сетку
5–40k/512. Ниже первого бина замера `interp_1d` клампит к граничному значению →
вместо продолжения спада получается полка.

Замер (Gaussian HP 80, min-phase, 65536 @48k, тот же таргет, отличие только в сетке):
DC gain 0.00271 (−51.3 dB) на экспортной сетке против 0.04240 (−27.5 dB) на сетке
замера, макс. разница импульсов −52.2 dB отн. пика. Пользователь получает файл,
которого не видел.

**Фикс:** передавать ту же сетку из `generateBandImpulse` — второй вызов станет
попаданием в кэш.

### H3. Окно Дольфа–Чебышёва вешает приложение
`fir/windowing.rs:136-164` — O(n²), `generate_half_window` строит окно длины 2n,
а `iterative_refine` пересоздаёт окно на каждой итерации (4 построения за вызов).
Замер: 16384 тапов → **46 с**; 65536 → ≈12 мин. Тело `generate_model_fir` синхронное
→ блокирует воркер, отмены нет.

**Фикс:** вынести построение окна из цикла (×4 бесплатно для всех окон);
переписать через ОБПФ (O(n log n)) или ограничить тапами ≤8192.

### H4. Клик по галочке легенды на IR/Step пересчитывает весь DSP
`FrequencyPlot.tsx:1546-1556` — чисто визуальные тумблеры (легенда, dB/Lin, ZONES,
SNAP) дёргают `setIrRenderTrigger` → полный `renderTimeTab`: ≈65 IPC-вызовов,
15 из них многомегабайтные. 0.3–1.5 с фриза на клик, заметно с 2 полос.
Ни один per-band вызов не идёт через кэш b141.7 — это прямые `invoke`,
дублирующие `evaluateBandFull`.

### H5. `compute_impulse` возвращает массив времени
`dsp/impulse.rs:52-64` — ось равномерна (`t[k] = (k−pre)·dt`), но сериализуется
целиком: 2.7 МБ при 65536, 11.3 МБ при 262144. При 15 вызовах на рендер —
40–170 МБ JSON. Фикс тот же, что уже сделан в b141.6 для FIR-payload: вернуть
`dt` + `pre_count`.

### H6. PEQ: sample rate не участвует в проверке устаревания
`stores/peq-optimize.ts:153` оптимизирует на `exportSampleRate()`, но
`captureOptimizedTarget` его не сохраняет → смена SR 48→96 k после оптимизации
не помечает PEQ устаревшим. Там же `filterEquals` не сравнивает `linear_phase`
и `subsonic_protect`.

## Mixed-phase bandpass (отдельный запрос)

**Достижимо из UI в два клика** — «Lin-φ» это поле каждого фильтра
(`types.ts:32`), блоки ФВЧ и ФНЧ независимы (`ControlPanel.tsx:221,241`),
изоляция закреплена тестом. Связанные полосы могут создать смешанную
конфигурацию сами при пропагации (`bands.ts:558-620`).

Маршрут: `route.ts:105` → `phase_mode: MixedPhase` → `dispatch.rs:67` отвергает
linear_phase для IIR → **cepstral**, `use_model_phase = true`, фаза берётся
вербатим из модели (минфазовая секция — Гильберт, линейная — ноль), пик
центрируется, полное окно, N/2 вычитается из realized-фазы.

Замер (LR4 HP 200 + LR4 LP 2000, 32768 тапов @48k, Blackman, iterations=3):

| конфиг | пик (N/2=16384) | Δmag 60–8000 | Δφ vs модель | pre-ring |
|---|---|---|---|---|
| HP min + LP lin | 16396 | ≤ 0.01 dB | ≤ 0.3° | 2.06 мс |
| HP lin + LP min | 16407 | ≤ 0.01 dB | ≤ 0.1° | 12.77 мс |
| обе lin | 16384 | — | 0.0° | 12.71 мс |

Предзвон локализован ровно у линейной секции: доля энергии до пика на 125/250 Гц —
98%/36% при линейном ФВЧ против 5%/4% при минфазовом.

**Вывод: работает корректно.** Ни паники, ни подмены на одну фазу. Тезис в
CLAUDE.md/MEMORY «single FIR не может mixed phase без артефактов — ограничение
физики» **устарел** (верен до b141.2) — как и комментарий-источник
`evaluate.ts:356-362`. Ограничение было реализационным и снято.

Дефекты рядом: ярлык фазы на Export-табе показывает «Min-Phase» для
HP=min+LP=lin (`FrequencyPlot.tsx:1802` — AND вместо XOR); предикат
`route.ts:105` не покрыт ни одним тестом; единственный фазовый тест
(`fir/tests.rs:561`) идёт с `iterations: 0`.

Цена центрирования при коротких тапах: 4096, HP min 40 + LP lin 400 → Δφ 10.5°,
Δmag 0.13 dB. На дефолтных 65536 — 0.1°.
